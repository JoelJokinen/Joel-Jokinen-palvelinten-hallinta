H1 – Hei Ansible

Tässä raportissa käsittelen palvelinten hallinnan H1-tehtävää, jossa asennetaan SSH-demoni, automatisoidaan SSH-kirjautuminen julkisella avaimella ja tutustutaan Ansibleen. Tehtävässä käytän Debian Linux -käyttöjärjestelmää.

a) Paikallista

Aikaisemman tehtävän raportti löytyy osoitteesta: H0 – Oikeasti netissä .

b) Sshecrets – SSH-demonin asentaminen

Ensimmäisenä kirjauduin Debianiin ja päivitin pakettiluettelot komennolla apt update. Sen jälkeen asensin SSH-demonin komennolla apt install openssh-server. Komento asentaa OpenSSH-palvelimen, jonka avulla koneeseen voidaan muodostaa SSH-yhteys.

Terminal – Debian (root)
apt update
apt install openssh-server

Seuraavaksi suoritin komennon systemctl enable --now ssh. Se asettaa SSH-demonin käynnistymään automaattisesti koneen käynnistyessä ja käynnistää sen samalla heti. Tämän jälkeen tarkistin demonin tilan komennolla systemctl status ssh.

Terminal – SSH-palvelun käynnistäminen
systemctl enable --now ssh
systemctl status ssh

Lopuksi testasin SSH-yhteyden muodostamista kirjautumalla omalle koneelleni komennolla ssh joel@localhost.

Terminal – SSH-yhteyden testaaminen
ssh joel@localhost

c) Pubkey – SSH-kirjautumisen automatisointi

SSH-kirjautumisen automatisointia varten tarvitaan julkinen ja yksityinen SSH-avain. Olin luonut avainparin jo aikaisemmassa tehtävässä, joten en luonut uutta. Avainparin luominen onnistuu komennolla:

Terminal – SSH-avaimen luominen
ssh-keygen -t ed25519

Komento kysyy ensin avaimen tallennuspaikkaa ja sen jälkeen mahdollista salalausetta eli passphrasea. Salalauseen voi jättää tyhjäksi, jolloin avaimen käyttö on helpompaa, mutta tällöin yksityinen avain ei ole suojattu salalauseella.

Seuraavaksi kopioin julkisen avaimen localhost-koneelle komennolla ssh-copy-id joel@localhost. Komento kysyi käyttäjän salasanaa ja lisäsi julkisen avaimen käyttäjän authorized_keys-tiedostoon. Tiedoston sijainti on /home/joel/.ssh/authorized_keys.

Terminal – Julkisen avaimen kopiointi
ssh-copy-id joel@localhost

Tämän jälkeen testasin kirjautumisen uudelleen komennolla ssh joel@localhost. Nyt kirjautuminen onnistui julkisella avaimella ilman käyttäjän salasanan kysymistä.

d) Hei Ansible – Ansiblella automatisointi

Ensimmäisenä asensin Ansible-ohjelmiston Debianille root-käyttäjällä komennolla apt install ansible. Asennuksen jälkeen tarkistin version komennolla ansible --version.

Terminal – Ansible asennus
apt install ansible
ansible --version

Seuraavaksi loin Ansible-projektia varten oman kansion komennoilla mkdir ansible-hello ja cd ansible-hello. Projektin sisälle loin inventaariotiedoston nimeltä hosts.ini.

Terminal – Projektikansion luominen
mkdir ansible-hello
cd ansible-hello
nano hosts.ini

Täytin hosts.ini-tiedoston seuraavalla rivillä:

hosts.ini
localhost ansible_connection=ssh ansible_user=joel ansible_ssh_private_key_file=/home/joel/.ssh/id_ed25519

Tiedosto määrittelee kohdekoneen eli localhostin, yhteystavaksi SSH:n, käytettäväksi käyttäjäksi joelin ja käytettävän yksityisen SSH-avaimen sijainnin.

Testasin seuraavaksi, että Ansible pystyy muodostamaan SSH-yhteyden ja suorittamaan komentoja kohdekoneella. Käytin tähän uptime-komentoa.

Terminal – Ansible SSH-yhteyden testaaminen
ansible all -a 'uptime' -i hosts.ini

Seuraavaksi loin Ansiblelle asetustiedoston ansible.cfg. Määrittelin siinä inventaariotiedoston automaattisesti käytettäväksi ja otin käyttöön tehtävien argumenttien tulostamisen.

ansible.cfg
[defaults]
inventory = hosts.ini
display_args_to_stdout = true

Tämän jälkeen loin site.yml-tiedoston, joka määrittelee, mitä rooleja kohdekoneella suoritetaan. Tässä tapauksessa halusin suorittaa hello-roolin kaikilla inventaariossa määritellyillä koneilla.

site.yml
- hosts: all
  roles:
    - hello

YAML-tiedostoja kirjoittaessa on tärkeää kiinnittää huomiota sisennyksiin. Sisennyksissä käytetään välilyöntejä eikä sarkainnäppäintä.

Seuraavaksi loin Hello-roolin vaatiman kansiorakenteen ja tehtävätiedoston.

Terminal – Hello-roolin luominen
mkdir -p roles/hello/tasks/
nano roles/hello/tasks/main.yml

Kirjoitin main.yml-tiedostoon seuraavan koodin:

roles/hello/tasks/main.yml
- copy:
    dest: /tmp/hello-ansible
    content: "Hahaa ansiblehan toimii!\n"

Koodissa määritellään copy-moduuli, joka luo kohdekoneelle tiedoston /tmp/hello-ansible. Tiedoston sisältö määräytyy content-kohdassa määritellyn tekstin perusteella.

Kun kaikki tiedostot ja kansiot olivat valmiina, suoritin Ansible-playbookin komennolla:

Terminal – Playbookin suorittaminen
ansible-playbook site.yml

Komento suoritti site.yml-tiedostossa määritellyn hello-roolin. Onnistuneessa suorituksessa Ansible ilmoittaa tehtävien tilat. Esimerkiksi changed tarkoittaa, että kohdekoneella tehtiin muutos. (Kuva 3.)

Lopuksi varmistin, että tiedosto todella syntyi kohdekoneelle ja että sen sisältö oli oikein. Tein tarkistuksen SSH:n kautta seuraavalla komennolla:

Terminal – Luodun tiedoston tarkistaminen SSH:n kautta
ssh joel@localhost 'cat /tmp/hello-ansible'
Tehtävän lopputulos: Ansiblella onnistuttiin muodostamaan SSH-yhteys localhost-koneelle ja luomaan kohdekoneelle tiedosto automaattisesti määritellyllä sisällöllä.
