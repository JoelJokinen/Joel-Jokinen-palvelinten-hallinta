<h1>H1 – Hei Ansible</h1>

<h2>x) SSH public key – Login without password</h2>

<p>SSH:lla voidaan kirjautua palvelimelle ilman salasanan kirjoittamista joka kerta. Tätä varten luodaan SSH-avainpari komennolla:</p>

<ul>
    <li><code>ssh-keygen</code></li>
</ul>

<p>Julkinen avain kopioidaan toiselle koneelle komennolla:</p>

<ul>
    <li><code>ssh-copy-id localhost</code></li>
</ul>

<p>Avain tallentuu <code>~/.ssh/authorized_keys</code>-tiedostoon ja kirjautuminen onnistuu tämän jälkeen automaattisesti.</p>

<p>SSH-palvelin asennetaan komennoilla:</p>

<ul>
    <li><code>sudo apt-get update</code></li>
    <li><code>sudo apt-get install ssh</code></li>
</ul>

<p>Se käynnistetään komennolla:</p>

<ul>
    <li><code>sudo systemctl enable --now ssh</code></li>
</ul>

<p>Yhteyttä voidaan testata komennolla:</p>

<ul>
    <li><code>ssh localhost</code></li>
</ul>

<p><strong>Oma huomio:</strong> SSH-avaimella kirjautuminen on helpompaa kuin salasanan kirjoittaminen joka kerta. Yksityinen avain on kuitenkin tärkeää pitää hyvässä tallessa.</p>

<h2>Hello Ansible</h2>

<p>Ansible on työkalu, jolla voidaan automatisoida ja ohjata muiden tietokoneiden hallintaa. Se toimii SSH-yhteyden kautta.</p>

<p>Ansible asennetaan komennolla:</p>

<ul>
    <li><code>sudo apt-get install ansible</code></li>
</ul>

<p>Hallittavat koneet määritellään <code>hosts.ini</code>-tiedostossa. Yhteyden testaamiseen käytetään esimerkiksi komentoa:</p>

<ul>
    <li><code>ansible all -a 'uptime' -i hosts.ini</code></li>
</ul>

<p>Tällä voidaan suorittaa komento kaikilla määritellyillä koneilla. <code>ansible.cfg</code>-tiedostossa voidaan määritellä asetuksia. Näin <code>-i hosts.ini</code>-parametria ei tarvitse lisätä jokaiseen komentoon.</p>

<p><code>site.yml</code>-tiedostossa määritellään, mitkä roolit koneilla suoritetaan.</p>

<p><strong>Oma huomio:</strong> YAML-kieltä on viheliäistä kirjoittaa, sillä syntaksin kanssa pitää olla tarkkana. Sisennykset tehdään esimerkiksi välilyönneillä eikä tabulaattorilla. Ansible vaikuttaa hyödylliseltä työkalulta, kun samoja asetuksia pitää tehdä usealle palvelimelle.</p>
<h2>b)</h2>
<p>
Ensimmäisenä kirjauduin Debianiin ja runasin apt updaten. Sitten apt install openssh-server, komento asensi ssh-demonin. Sen jälkeen systemctl enable --now ssh, joka asettaa demonin käynnistymään koneen startupissa ja loppuosa käynnistää sen heti. Sen jälkeen vielä testataan sen tila komennolla systemctl status ssh (Kuva 1). Sitten vielä testattiin kirjautumalla SSH:lla, komennolla ssh joel@localhost.
</p>

<h2>c)</h2>
<p>
Jotta voidaan automatisoida SSH-kirjautuminen, täytyy luoda avainpari. Sen olinkin jo aikaisemmassa tehtävässä tehnyt, joten nyt en tehnyt sitä. Kuitenkin komento menee jotakuinkin näin: ssh-keygen -t ed25519. Ensin se kysyy, minne tallennetaan ja sitten passphrasea. Itselläni tässä on passphrase, mutta sitä ei tarvitse. Jos sitä ei laita, tekee se harjoituksen tekemisestä helpompaa, sillä sitä ei kysytä joka kerta kun localhostiin on yhdistämässä.
</p>

<p>
Seuraavaksi kopioidaan julkinen avain komennolla ssh-copy-id joel@localhost, annettiin käyttäjän salasana ja komento lisäsi avaimen tiedostoon /home/joel/.ssh/authorized_keys. Sitten vain testataan kirjautuminen komennolla ssh joel@localhost ja nyt pääsin kirjautumaan suoraan SSH-avaimella (kuva 2).
</p>

<h2>d)</h2>
<p>
Ensimmäisenä latasin Debianilleni Ansiblen root-käyttäjällä komennolla apt install ansible. Ansiblen version voi tarkistaa komennolla ansible --version. Seuraavaksi loin ansible-projektin kansion komennoilla: mkdir ansible-hello ja cd ansible-hello, sekä loin hosts.inin: nano hosts.ini ja täytin sen riveillä:
</p>

<pre>localhost ansible_connection=ssh ansible_user=joel ansible_ssh_private_key_file=/home/joel/.ssh/id_ed25519</pre>

<p>
Tiedosto määrittelee kohdekoneen (localhost), muodostaa yhteyden SSH:lla, määrittelee käytettävän käyttäjän ja yksityisen SSH-avaimen. Testasin vielä Ansiblen SSH-yhteydellä suorittamalla: ansible all -a 'uptime' -i hosts.ini komennon.
</p>

<p>
Seuraavaksi loin Ansiblen asetustiedoston komennolla nano ansible.cfg ja kirjoitin sinne rivit:
</p>

<pre>[defaults]
inventory = hosts.ini
display_args_to_stdout = true</pre>

<p>
Tämän jälkeen Ansible löytää hosts.inin automaattisesti.
</p>

<p>
Sitten loin site.yml-tiedoston komennolla nano site.yml ja täytin sen riveillä:
</p>

<pre>- hosts: all
  roles:
    - hello</pre>

<p>
.yml-tiedostoja tehdessä on tärkeää oikea syntaksi!
</p>

<p>
Seuraavaksi luotiin Hello-rooli seuraavasti: Luotiin kansio ja rooli komennoilla mkdir -p roles/hello/tasks/ ja nano roles/hello/tasks/main.yml. Tiedosto täytettiin koodilla:
</p>

<pre>- copy:
    dest: /tmp/hello-ansible
    content: "Hahaa ansiblehan toimii\n"</pre>

<p>
Näin määriteltiin, että Ansible luo kohdekoneelle tiedoston, jonka sisällä on tervehdys.
</p>

<p>
Seuraavaksi voitiin suorittaa ansible-playbook site.yml ja onnistunut tulostus näyttää esimerkiksi, jos tiedostoon on tehty muutoksia (kuva 3).
</p>
